# 市场参照：相邻产品怎么处理颜色

看的是与案屿相邻的四类界面：并行 agent / worktree 工具、项目协作工具。重点不是抄配色，而是看它们把颜色放在哪。

## 看过的东西

| 产品 | 类型 | 看到的做法 | 来源 |
|---|---|---|---|
| Conductor | 并行 agent / worktree 桌面工具 | 深炭黑界面，几乎单色；颜色只出现在状态、diff、运行操作。界面本身先退后。 | [Conductor Docs](https://www.conductor.build/docs/guides/git-worktrees/run-codex-with-git-worktrees) |
| Crystal | 多 agent / 多 worktree 桌面工具 | 深蓝灰底，一个蓝色主按钮；绿/红只用于代码 diff，状态点很小。 | [cicero-im/crystal](https://github.com/cicero-im/crystal) |
| Vibe Kanban | agent 任务看板 | 应用本体是白/浅灰，黑字；颜色只出现在代码差异、状态与少量强调。落地页用奶油纸 + 黑 + 陶土红。 | [Vibe Kanban Docs](https://vibekanban.com/docs/workspaces) |
| Linear（2026 界面刷新） | 项目协作 / issue 工具 | 默认主题从偏冷蓝改为“更暖的灰、更低饱和”；侧栏主动变暗，边框变少、变软，图标缩小。 | [Linear: A calmer interface](https://linear.app/now/behind-the-latest-design-refresh) |

## 四条共同点

1. **界面本身几乎无色。** 大面积是黑/深灰/白/浅灰；颜色只做状态、差异、主操作。
2. **一个主强调色，最多再加语义色。** 不把品牌色刷到背景、正文、按钮、状态所有地方。
3. **层级靠明度与留白，不靠彩色容器。** Linear 的刷新甚至把侧栏调暗、边框变少，让主内容先被看到。
4. **注意力色和进行色分开。** 进行中用低饱和绿/蓝，待处理用暖色（陶土/琥珀），互不抢。

## 对案屿的直接结论

- 现在 B×A 的问题不是“绿不对”，是**绿同时做了纸、字、按钮、印章、边线五种角色**，所以像一整页绿色滤镜。绿应该只做“有生命 / 进行中”的信号。
- 纸面回到中性：暖灰纸或冷灰纸都可以，不再用带绿底的纸。
- 主操作（添加项目、交接、复制）用墨色，而不是品牌绿；这样绿才退得回去。
- 陶土红/琥珀只留给“待检查、久未更新、需要人处理”的状态。
- 苔绿保留在：品牌标记、进行中印章/左线、焦点环。占画面几个百分点即可。

## 两版收敛

- `05-bxA-neutral.html`：暖中性纸 + 墨色主操作；苔绿只做进行中状态，陶土红只做提醒。最接近 A 的气质，但不再过绿。
- `06-bxA-cool.html`：冷中性纸 + 墨色主操作；进行中改用蓝灰，苔绿只留在品牌标记。更工具感，绿只剩一个“意思”。

两版都保留 B 的结构、字号与间距，只换颜色与主按钮处理，便于直接比较。
