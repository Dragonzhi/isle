# 案屿 Isle · v0.1

本机项目看板：记住每个项目停在哪里，明天打开就能继续。

## 启动

需要 Node.js 24 或更高版本。双击桌面上的「案屿」快捷方式（等同双击仓库里的 `启动案屿.cmd`）即可：首次会安装依赖并构建页面，之后启动本机服务并自动在默认浏览器打开看板。同一状态目录同时只跑一个实例，重复双击会直接打开已运行实例的页面。关闭终端窗口即停止服务。

之后每次启动，若 `src`、`shared`、`public` 等构建输入比 `dist` 新，会先自动重建页面；构建失败时沿用上一次的构建结果，仍然打开看板。需要重新创建快捷方式时运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\create-shortcut.ps1
```

快捷方式的图标会先复制到 `%LOCALAPPDATA%\Isle\isle.ico` 再指过去：Windows 解析 .lnk 图标路径时不支持含中文的路径，直接指向仓库里的 `public\isle.ico` 会显示成白纸图标。

也可以手动启动（只起服务、自己打开终端打印的地址）：

```powershell
npm install
npm run build
npm start
```

`node tools\launch.ts --open` 等价于双击快捷方式（按需构建 + 启动 + 打开浏览器）。启动链接建立本机会话后会自动移除地址中的 token；服务重启后需使用新的启动链接。端口被占用时顺延，同一状态目录的重复启动会打印并打开已有实例地址。

开发时使用 `npm run dev`，前后端由同一个本机服务提供。修改前端后刷新页面；修改后端后重启。

## 第一条记录

首页按项目组织：普通项目以双列卡片展示，落单卡片填满当前行，窄屏自动切为单列。每张卡片突出项目名和下一步，底部常驻记录更新时间及“开工 / 收工”入口；下一步可直接在卡片内编辑。同一项目已登记多个 git worktree 时，以完整项目外框包住各工作区：主工作区独占一行，分线在内部双列展示，框内外使用独立布局。筛选或折叠后只剩一个工作区也保留项目框，并显示可见／总数。顶部与侧栏按项目计数，另外列出工作区数，例如“6 个项目 · 8 个工作区”；每个 worktree 仍有独立记录，可手动添加目录，也可从项目页顶部“添加已有工作区”勾选导入。项目页「建工作区」可生成交给 Agent 的建 worktree 指令（工作区词），你复制给它执行；案屿只出词，不执行。基准分支从该项目已有的本地分支中选择、默认当前分支，也可自定义为远端分支或提交。建好后用「添加已有工作区」登记并各装一次 Skill；Agent 配置与依赖不会跟着 worktree 复制，每个目录还要由你另开一个 Agent 会话，把工作目录切过去。

每张卡片底部的星标按钮用于「特别关注」：点一下该项目排到看板最前，卡片上出现“特别关注”标签；再点一次取消。工具条多一个「特别关注」页签，只看这些项目并在此增删。这份清单只存在本机浏览器里（`isle.pinned`），不进 `TASKS.md`、不出网、也不影响别人看到的记录；换浏览器或清掉站点数据即丢失，需要长期保留请另记在项目文件里。

项目详情采用任务优先布局：顶部突出下一步，随后显示进行中和待办，已完成默认折叠；交接摘要及工作留痕放在后面。任务正文为 17px，摘要为 16px；留痕按时间线排版，摘要沿页面自然展开。摘要带日期的轮次节超过 3 节、或留痕超过 12 条时，页面给出按窗口压缩的提示，只提示不改文件。任务行右侧可用铅笔就地改标题，或完成、删除任务；标题编辑保留复选框、缩进和末尾 @标签，写入带冲突检测与备份，展开已完成不会修改文件。项目页 Git 历史只读预览，只列非合并提交并默认显示最近 12 条，可展开全部；它用于核对工作留痕是否真的提交，不代替留痕里的结论与验证。

1. 点击“添加项目”，粘贴一个本机绝对目录路径，项目名可留空。
2. 如果项目已有 `TASKS.md`，添加时原样读取；没有则生成模板。默认同时安装项目 Skill，可取消勾选；官方旧版会升级，改过的同名文件不覆盖。
3. 在首页点击续接提示，写一句“停在哪里；下一步做什么”，回车保存、Esc 取消。
4. 点击项目名查看任务和交接摘要；“收工回写”面向当前 Agent，“交给新 Agent”面向下一家。
5. 按 `c` 可直接复制所选项目的开工词，复制前会重新读取记录。
6. 外部 Agent 回写后刷新。日期仅表示记录更新。
7. 项目页「打开目录」用系统文件管理器打开该项目的目录，之后可在其中用编辑器或 VS Code 打开；案屿只打开目录，不启动编辑器或 Agent。

## 一个项目的多个工作区

1. 已有 Git worktree 时，打开项目详情顶部的“添加已有工作区”。案屿只在你点击时读取该仓库的工作区列表，不扫描磁盘或后台登记。
2. 列表展示分支与绝对路径，已登记或不可用的目录不能勾选；可修改各自的看板名称，选择是否补齐案屿 Skill，然后“添加所选”。可从主目录或任一已登记工作区进入。
3. 每个选中目录沿用原添加流程，保留已有 TASKS.md；没有记录时创建模板。登记前重新检查仓库归属、路径和清单冲突，不能把请求中的任意路径冒充该项目工作区。批量添加逐个保存，某个失败会保留此前成功项并明确提示，剩余选择保留供核对。
4. 首页自动归成一个项目框，框头也可直接添加已有工作区；详情里的“主工作区”表示目录角色，不等同于分支必须叫 main。任务与 next 仍各自独立，不增加另一套项目数据库。

Git 工作区隔离已跟踪代码，不会替你隔离链接回主目录的源码、忽略文件或运行数据。会修改的技能应有独立副本；插件若另有仓库，应使用那个仓库的独立分支／工作区。已有任务副本也可能过时，首次开工需按方向整理；合并外层代码不代表插件、私有技能和任务记录已一起合并。案屿只列出与登记，不替你创建、删除、运行或合并工程。

## 换一家 Agent 接着做

1. 离开当前 Agent 前，在项目页点“收工回写”，选择“本次署名”，复制收工词，粘贴到正在工作的对话。侧栏“Agent 名单”可维护常用名称。
2. 当前 Agent 先维护 `TASKS.md` 的 `## 待办`、`## 进行中`、`## 已完成`：同步本次相关任务状态，补上实际处理过但原来没列出的工作，以及明确的下一步行动项；复用已有条目，不重复建任务。已完成只保留最近 14 天且最多 40 条；完成时在标题末尾记 `（YYYY-MM-DD）`，超出由回写时按旧到新删除。
3. 再写 `## 交接摘要`：每轮新起一个 `### YYYY-MM-DD 标题` 节，按「变更／依据／验证」写，补充结论、为什么这样做及证据强度、验证结果、阻塞和续接上下文；带日期的轮次节只保留最近 3 轮，超出从最旧删起，删前先把仍起作用的阻塞、未验证与下一步并入最新节或任务清单。再在 `## 工作留痕` 末尾追加本次贡献及署名，留痕只保留最近 14 天且最多 12 条；最后更新 `next` 与 `updated`。摘要不能替代任务清单。没有新增行动项的纯讨论可以保持任务清单不变，并说明原因。
4. 回到案屿点“已回写，刷新记录”，同时核对任务列表和摘要。复制按钮只复制指令，不代表已经回写；文件没有变化时会明确提示。
5. 切到“开工词”，可另选接手 Agent，填写本次目标、完成标准，再复制给下一家。完整提示词带上摘要，Skill 短指令让 Agent 直接读项目记录；两者都要求先核对实际状态，再按本次目标继续。接手方读摘要只需看最近 3 节——旧节是历史索引，和 `next` 或任务清单冲突时以后两者为准。接手 Agent 与收工署名分开选择，避免换人后误签。

打开或复制交接词时都会重新读取本机文件。预览期间记录若又变了，会先刷新预览，保留你填写的目标和完成标准，核对后再复制。列表首个进行中任务只是参考，不自动决定这次交给下一家的工作。

Agent 没有写回、无法直接写文件，或者你只想补一句时，可在项目页点“手动补记”，粘贴并保存摘要。摘要是自由文本，不新增必填字段，推荐记录：

```markdown
## 交接摘要

- 已确认：修改了 src/render.ts 的材质处理。
- 验证：npm test 通过；界面未验证。
- 未完成：缺少极端输入的样例。
- 接着做：先补样例，再验证界面。
```

摘要可包含列表、闭合的代码块和 `###` 小标题，其中的说明不会被识别为任务。没有摘要的旧文件照常使用；读取或复制不会自动迁移文件，首次补记时才新增该分节。文件名仍为 `TASKS.md`。

固定分节名不建议追加日期或署名，交接词会明确提醒。为兼容 Agent 已经写出的标题，`## 交接摘要（2026-10-17）` 和 `## 交接摘要 (2026-10-17)` 也会识别为摘要，工作留痕采用相同规则。仅兼容末尾配对中／英文括号内的 `YYYY-MM-DD`，不按任意前缀猜测分节。保存摘要时保留原标题和日期，不另建一节；标题日期不代替 `updated`。同一文件有多个标准或带日期的摘要时合并展示并提示，手动保存前需在原文件中确认合并，不自动只保留最新日期那节。

摘要以 Markdown 展示，支持标题、粗体、列表、表格、引用与代码块；“手动补记”仍编辑原文。右上角“复制摘要”会重新读取最新记录，复制原始 Markdown，便于直接粘给 Agent 或其他编辑器。收工弹窗中的摘要预览使用相同渲染。原始 HTML 不执行，图片以文字占位显示，不自动请求远程图片。

## 项目级案屿 Skill

添加或重新指向项目时，默认勾选“安装项目级案屿 Skill”，可取消。已有项目进入详情页，点击“项目 Skill → 安装 / 补齐”。只在你明确给出的项目目录内补充以下文件：

| 文件 | 用途 | 证据 |
| --- | --- | --- |
| `.agents/skills/isle/SKILL.md` | 通用开工与收工规范；Codex、DeepSeek Harness、Trae、ZCode 都会从这个共享目录发现它 | 本机实测 |
| `.agents/skills/isle/agents/openai.yaml` | Codex 显示名称与默认指令 | 本机实测 |
| `.claude/skills/isle/SKILL.md` | Claude Code 入口，指向通用规范 | 本机实测 |
| `.trae/skills/isle/SKILL.md` | Trae 入口，指向通用规范 | 本机实测 |
| `.zcode/skills/isle/SKILL.md` | ZCode 入口，指向通用规范 | 本机实测 |
| `AGENTS.md` 里的受管区块 | Codex、Trae、DeepSeek Harness 的项目规则文件；只在 `isle:begin` 与 `isle:end` 之间写入 | 本机实测 |
| `CLAUDE.md` 里的受管区块 | Claude Code、DeepSeek Harness 的项目规则文件；同上 | 本机实测 |

落点表在 `server/adapters.ts`，每条带证据档：**本机实测**（从已安装的该 Agent 代码或行为里核实过落点，默认安装）、**仅文档**（官方文档记载、本机未实测，默认安装但界面标「未实测」）、**未核实**（只有传闻，默认不安装）。新增一家 Agent 只往表里加一行，不改逻辑。

**默认只装共享包，其余 Agent 用选择器加。** 新项目只写 `.agents/skills/isle/`（规范正文 + Codex 元数据），所以目录里只多一个 `.agents`；需要 Claude Code、Trae、ZCode 的专属入口或 `AGENTS.md` / `CLAUDE.md` 的受管区块时，在项目页「项目 Skill」的「添加落点」里选一家再点「添加」，才会创建对应文件。面板顶部用「默认 / 按需 / 写入 / 删除」四行说明这套规则，不用读长段落。已添加的落点可以「删除」：先弹一个确认框说清会删什么、留什么，确认后只清案屿写进去的字节（官方版本整文件、受管区块块内），你改过的会留下并说明原因，因案屿变空的目录一并收回——所以删掉 ZCode 就不会留下一个空的 `.zcode`。基础包是各入口共用的规范正文与元数据，行尾标「基础包」、不能删除；要清空整个项目 Skill，用面板右上角的「撤除」。选择按项目 id 记在本机 `settings.json` 的 `skillTargets`，旧版的 `skillMarkers` 开关读取时等价、第一次改动时迁移。

现在可以直接对当前项目的 Agent 说：

```text
使用 isle（案屿）Skill 收工回写，署名 Codex。
```

开工时说“使用 isle Skill 开工，本次目标是……，完成标准是……，署名 OpenCode”。Codex 可通过 `$isle` 显式选择，Claude Code 可用 `/isle`；工具未发现时，直接要求读取项目内 `.agents/skills/isle/SKILL.md`。Skill 统一要求先维护任务清单、再合并摘要、追加本轮署名留痕，最后更新 next 与本地日期；不把收工变成额外实现、补跑验证或提交代码。

交接弹窗提供“Skill 短指令 / 完整提示词”。安装全部就绪时默认短指令，仍附项目路径、所选署名、开工目标与完成标准，以及直接读取规范的路径；未安装或存在冲突时默认完整提示词。打开、复制时重新读取项目和安装状态；预览后通用规范被修改时阻止复制短指令，提示检查或切换完整提示词。完整提示词可随时使用。

安装会补齐缺失文件，并把**官方旧版**升级到当前版本：内容逐字节比较，等于某个已发布版本（`skills/isle/history.json` 记录的 sha256）时视为官方旧副本、可直接替换；对不上的一律视为用户自有文件，标为冲突并保留，永不覆盖。通用规范冲突时不新增其他入口，避免把 Agent 导向未知规则。补齐失败会显示具体文件状态，项目仍可使用完整提示词；首次安装需要文件系统支持硬链接。安装不改全局配置或忽略规则，不因为读取或复制就安装；移出看板或重新指向不会删除原项目的 Skill。安装与项目登记不是跨文件事务，登记失败前已创建的文件会保留。

“项目 Skill → 检查”是干跑：逐条列出会发生什么（新建、追加区块、替换、跳过、冲突、无法处理），没添加的落点报「跳过」，不写任何文件。“项目 Skill → 撤除”只撤案屿写进去的字节：官方版本的整文件删除，你改过的同名文件保留；`AGENTS.md` / `CLAUDE.md` 只删受管区块，文件本身保留。撤除不区分是否添加过——以前装过、现在不在列表里的落点，残留字节也一并按版本判定清掉，变空的目录一并收回；非空目录（你自己还放着 Skill 的）一律保留，`TASKS.md` 不动。撤除结果不会静默成功：检查与撤除的结果收在面板里的一张结果卡上，先给结论和数量，再列出需要你留意的文件与原因，最后给出下一步，可随时收起；右上角提示改为图标加一句话，成功 4.5 秒自动收起。

**`AGENTS.md` / `CLAUDE.md` 也要手动添加。** 添加后才往已存在的规则文件末尾追加一段受管区块，块外一字不动；用 ``<!-- isle:begin -->`` / ``<!-- isle:end -->`` 标记，只写指针不复制规范正文。规则文件不存在时不创建——不替用户在没有约定的项目里凭空建规则文件。重装只替换块内内容，多份区块收敛为一份，缺少一半标记时不写并报错让你手动检查；块内写入失败会保留原文件。这些文件通常被 git 跟踪，所以默认不添加；添加状态与其余落点一起记在本机 `settings.json` 的 `skillTargets`，按项目保存。

目录依据：[AGENTS.md 约定](https://agents.md)、[Claude Code Skills](https://code.claude.com/docs/en/skills)、[Trae Skills](https://docs.trae.ai/ide/skills)；DeepSeek Harness 的 `.dsh/skills`（rank 100）与 `.agents/skills`（rank 200）、ZCode 的 `.zcode/skills` 与 `.agents/skills` 来自本机安装包内实际代码，没有公开文档页。这实现了发现入口和规范分发，**尚未实测五家 Agent 在真实会话中的发现与回写遵从率**——界面按落点证据档标出「未实测」，不把没验证过的说成已验证。可刷新工具的 Skill 列表或重启 Agent。Skill 不会主动启动 Agent，也不会绕过工具权限。

## Agent 署名与工作留痕

侧栏“Agent 名单”初始提供 Codex、OpenCode、Trae，可每行填写一个名称保存，也可清空。名称不区分大小写去重，最多 50 个，每个不超过 60 字符，不能含控制字符、冒号或 `·`。名单是交接时的选择项，移除或改名不会更改历史署名。未选署名时，交接词要求 Agent 向你确认，不猜测具体模型。

任务行上的 `@codex` 等标签表示原计划交给谁；本次贡献由实际参与者在收工时署名。项目页“工作留痕”以 Markdown 展示 `TASKS.md` 中的同名分节：

```markdown
## 工作留痕

- 2026-10-16 · Codex：定位渲染入口；任务完成，未验证。
- 2026-10-17 · OpenCode：调整材质处理，兼容修复仍在进行；npm test 通过，界面未验证。
```

每轮追加实际贡献、对应任务状态和验证结果，部分推进也能留痕。摘要与留痕各自按窗口保留：摘要带日期的轮次节只留最近 3 轮、留痕只留最近 14 天且最多 12 条，超出从最旧删起，历史见 Git 提交与 `验收记录.md`；同一轮不要重复追加。留痕是 Agent 自述，不代表案屿独立验证结果。案屿不会因点击复制就生成工作记录，仍需把指令交给外部 Agent，回写后刷新。没有留痕的旧文件照常读取，首次回写时再新增分节。

首次自动创建模板使用同目录硬链接发布完整文件，适用于 NTFS 等支持硬链接的文件系统。遇到不支持的文件系统时会给出提示，可手动创建 UTF-8 的 `TASKS.md` 后重新添加；不会降级为覆盖写入。

首页快捷键：`j` / `k` 选择项目，`Enter` 查看，`c` 复制开工词，`Esc` 取消选择。输入时暂停全局快捷键。

项目页「打开目录」会在系统文件管理器中打开该项目的目录，之后可用自己的编辑器打开。Windows 调用资源管理器，macOS 调用 Finder，其他桌面用 `xdg-open`；请求只接受来自案屿页面、带本机会话、且属于清单中当前可读目录的调用，不经过 shell，不启动编辑器、Agent 或项目命令。

页面操作的结果（已打开目录、已保存、错误原因等）以右上角浮动提示显示：成功 5 秒、错误 9 秒后自动收起，也可点关闭按钮。提示不占正文布局。

## 文件与恢复

默认清单在 `%USERPROFILE%\.isle\projects.txt`，格式为 `绝对路径<TAB>可选项目名`，支持空行和 `#` 注释。坏行会给提示，其他项目保留。移出看板只删除清单条目，不删除项目文件。离线项目可重新指向目录；目录确实不存在时（例如已删除的 worktree），离线卡片上也能直接「移出看板」。

全局 Agent 名单保存在同目录 `settings.json` 的 `agents` 数组；各项目添加过的项目 Skill 落点记在同一文件的 `skillTargets` 对象里（`{ 项目 id: { 落点 key: true } }`，只记添加过的，缺省就是没有）。旧版的 `skillMarkers` 数组仍可读，等价于添加了两条规则文件落点，第一次改动时并入 `skillTargets`。保存会保留其他设置字段，页面接口只返回名单及冲突校验值，不返回其他设置内容。设置损坏时不覆盖原文件，项目记录仍可读取；设置在编辑期间被修改时拒绝覆盖，重新打开名单后核对再保存。

项目 Skill 的撤除（以及单条「删除」）只删案屿写入的字节：整文件按版本判定（等于当前模板或某个已发布 sha256 才删），受管区块只删 `isle:begin` 到 `isle:end` 与追加时补的那个空行，块外内容按字节原样保留；不看落点是否添加过。因案屿而变空的目录会被收回，但仍放着你自己的 Skill 的目录一律保留——`.claude/` 里可能还有别的技能；规则文件删完只剩空白时也保留文件。撤除是幂等的，重复执行只报「文件不存在」或「没有可删区块」。

`TASKS.md` 是唯一任务、交接摘要和贡献记录数据源。已有文件的 BOM、换行和未编辑内容保持原样；保存 `next` 或交接摘要仅改相应内容和 `updated`，保留工作留痕，不重排任务。两类编辑共用备份和冲突检测；文件被外部修改时拒绝覆盖，界面保留输入供核对。备份、临时文件准备失败时不替换原文件。

每次实际编辑前在项目目录生成 `TASKS.md.bak`，保存上一次写入前的完整字节。为识别本产品备份、防止覆盖用户自己的同名文件，`.bak` 使用带格式标记、目标路径和 SHA-256 的 JSON 容器，原文字节以 Base64 保存。它不是另一份任务源。未知格式的同名备份会阻止写入，需先另存。可这样导出备份原文：

```powershell
npm run restore -- "D:\work\my-project" "D:\work\my-project\TASKS-recovered.md"
```

导出文件必须不存在；此命令不覆盖 `TASKS.md`。核对原文后再自行恢复。`.bak` 只保留一份，不能替代项目的长期备份或 Git 提交。原子替换避免半截文件；不承诺消除所有外部程序并发写入的竞争窗口。

可通过环境变量 `ISLE_HOME` 指定状态目录、`ISLE_PORT` 指定起始端口，例如：

```powershell
$env:ISLE_HOME = Join-Path $PWD '.local-state'
npm start
```

应用只监听 `127.0.0.1`，校验 Host、Origin 和会话，写接口只接受 JSON。项目路径必须手动注册，拒绝链接跳转；不遍历目录，不访问外部服务。v0.1 不含模型、任务状态编辑或拖拽。

## 提交与分支

改动走短生命周期分支再合并，不直接提交到 `main`：

- 设计与方案修订用 `design/<主题>`，功能用 `feat/<主题>`，修复用 `fix/<主题>`，文档与流程类用 `chore/<主题>`
- 本地 `main` 只做快进（`git merge --ff-only origin/main`），不承接直接提交；发现落后先快进，再开分支
- 推分支后开 PR 合并，合并后删除远端分支；`backup/<日期>` 一类分支只是改动集中前的临时保险，确认无需要后同样删除
- 同一轮改动涉及的 `TASKS.md` 任务与`## 工作留痕` 跟着代码走，不拆成另一个 PR；署名写实际参与者

`gh` 未安装时用网页建 PR，分支名仍保持上面的前缀，便于按类型区分。这条约定本身就是一次 PR 的产物：v0.12–v0.13 的改动曾先直推 `main`，随后重做为 `design/v0.12-v0.13` 分支并走 PR #1 合并。

## 验证

```powershell
npm test
npm run build
```

自动检查覆盖脏文件容错、状态冲突、已有文件不变、BOM/CRLF、备份与并发写入、目录离线和重指向、清单坏行、链接防护、本机 API 认证，以及项目 Skill 默认只装基础包、选择器添加、行尾删除与空目录收回、同名冲突、旧开关迁移与短指令。首屏数据渲染耗时可在浏览器 Performance 中查看 `isle:projects-render`，项目卡片容器也记录 `data-render-ms`。真实项目三天使用验证仍需实际完成，不能用自动检查替代。
