# 案屿 Isle · v0.1

本机项目看板：记住每个项目停在哪里，明天打开就能继续。

## 启动

需要 Node.js 24 或更高版本。在当前目录运行：

```powershell
npm install
npm run build
npm start
```

也可双击 `启动案屿.cmd`。打开终端打印的完整 `http://127.0.0.1:4317/?token=…` 地址。启动链接建立本机会话后会自动移除地址中的 token；服务重启后需使用新的启动链接。端口被占用时顺延，同一状态目录的重复启动会打印已有实例地址。

开发时使用 `npm run dev`，前后端由同一个本机服务提供。修改前端后刷新页面；修改后端后重启。

## 第一条记录

首页以双列项目卡片展示，窄屏自动切为单列。每张卡片突出项目名和下一步，底部常驻记录更新时间及“开工 / 收工”入口；下一步可直接在卡片内编辑。

项目详情采用任务优先布局：顶部突出下一步，随后显示进行中和待办，已完成默认折叠；交接摘要及工作留痕放在后面。任务正文为 17px，摘要为 16px；留痕按时间线排版，摘要沿页面自然展开。任务状态仍只读，展开已完成不会修改文件。

1. 点击“添加项目”，粘贴一个本机绝对目录路径，项目名可留空。
2. 如果项目已有 `TASKS.md`，添加时原样读取；没有则生成模板。默认同时安装项目 Skill，可取消勾选；已有同名文件不覆盖。
3. 在首页点击续接提示，写一句“停在哪里；下一步做什么”，回车保存、Esc 取消。
4. 点击项目名查看任务和交接摘要；“收工回写”面向当前 Agent，“交给新 Agent”面向下一家。
5. 按 `c` 可直接复制所选项目的开工词，复制前会重新读取记录。
6. 外部 Agent 回写后刷新。日期仅表示记录更新。

## 换一家 Agent 接着做

1. 离开当前 Agent 前，在项目页点“收工回写”，选择“本次署名”，复制收工词，粘贴到正在工作的对话。侧栏“Agent 名单”可维护常用名称。
2. 当前 Agent 先维护 `TASKS.md` 的 `## 待办`、`## 进行中`、`## 已完成`：同步本次相关任务状态，补上实际处理过但原来没列出的工作，以及明确的下一步行动项；复用已有条目，不重复建任务。
3. 再写 `## 交接摘要`，补充结论、验证依据、阻塞和续接上下文；在 `## 工作留痕` 末尾追加本次贡献及署名，最后更新 `next` 与 `updated`。摘要不能替代任务清单。没有新增行动项的纯讨论可以保持任务清单不变，并说明原因。
4. 回到案屿点“已回写，刷新记录”，同时核对任务列表和摘要。复制按钮只复制指令，不代表已经回写；文件没有变化时会明确提示。
5. 切到“开工词”，可另选接手 Agent，填写本次目标、完成标准，再复制给下一家。完整提示词带上摘要，Skill 短指令让 Agent 直接读项目记录；两者都要求先核对实际状态，再按本次目标继续。接手 Agent 与收工署名分开选择，避免换人后误签。

打开或复制交接词时都会重新读取本机文件。预览期间记录若又变了，会先刷新预览，保留你填写的目标和完成标准，核对后再复制。列表首个进行中任务只是参考，不自动决定这次交给下一家的工作。

Agent 没有写回、无法直接写文件，或者你只想补一句时，可在项目页点“手动补记”，粘贴并保存摘要。摘要是自由文本，不新增必填字段，推荐记录：

```markdown
## 交接摘要

- 已确认：修改了 src/render.ts 的材质处理。
- 验证：npm test 通过；界面未验证。
- 未完成：缺少极端输入的样例。
- 接着做：先补样例，再验证界面。
```

摘要可包含列表、闭合的代码块和 `###` 小标题，其中的说明不会被识别为任务。没有摘要的旧文件照常使用；读取或复制不会自动迁移文件，首次补记时才新增该分节。文件名仍为 `TASKS.md`。

固定分节名不建议追加日期或署名，交接词会明确提醒。为兼容 Agent 已经写出的标题，`## 交接摘要（2026-10-17）` 和 `## 交接摘要 (2026-10-17)` 也会识别为摘要，工作留痕采用相同规则。仅兼容末尾配对中／英文括号内的 `YYYY-MM-DD`，不按任意前缀猜测分节。保存摘要时保留原标题和日期，不另建一节；标题日期不代替 `updated`。同一文件有多个标准或带日期的摘要时合并展示并提示，手动保存前需在原文件中确认合并，不自动只保留最新日期那节。

摘要以 Markdown 展示，支持标题、粗体、列表、表格、引用与代码块；“手动补记”仍编辑原文。右上角“复制摘要”会重新读取最新记录，复制原始 Markdown，便于直接粘给 Agent 或其他编辑器。收工弹窗中的摘要预览使用相同渲染。原始 HTML 不执行，图片以文字占位显示，不自动请求远程图片。

## 项目级案屿 Skill

添加或重新指向项目时，默认勾选“安装项目级案屿 Skill”，可取消。已有项目进入详情页，点击“项目 Skill → 安装 / 补齐”。只在你明确给出的项目目录内补充以下文件：

| 文件 | 用途 |
| --- | --- |
| `.agents/skills/isle/SKILL.md` | 通用开工与收工规范，Codex、OpenCode 的发现入口 |
| `.agents/skills/isle/agents/openai.yaml` | Codex 显示名称与默认指令 |
| `.claude/skills/isle/SKILL.md` | Claude Code 入口，指向通用规范 |
| `.trae/skills/isle/SKILL.md` | TRAE 入口，指向通用规范 |

现在可以直接对当前项目的 Agent 说：

```text
使用 isle（案屿）Skill 收工回写，署名 Codex。
```

开工时说“使用 isle Skill 开工，本次目标是……，完成标准是……，署名 OpenCode”。Codex 可通过 `$isle` 显式选择，Claude Code 可用 `/isle`；工具未发现时，直接要求读取项目内 `.agents/skills/isle/SKILL.md`。Skill 统一要求先维护任务清单、再合并摘要、追加本轮署名留痕，最后更新 next 与本地日期；不把收工变成额外实现、补跑验证或提交代码。

交接弹窗提供“Skill 短指令 / 完整提示词”。安装全部就绪时默认短指令，仍附项目路径、所选署名、开工目标与完成标准，以及直接读取规范的路径；未安装或存在冲突时默认完整提示词。打开、复制时重新读取项目和安装状态；预览后通用规范被修改时阻止复制短指令，提示检查或切换完整提示词。完整提示词可随时使用。

安装只创建缺失文件：已有同名文件逐字节比较，内容不同（包括旧版或手工修改）则标为冲突并保留，不自动升级。通用规范冲突时不新增其他入口，避免把 Agent 导向未知规则。补齐失败会显示具体文件状态，项目仍可使用完整提示词；首次安装需要文件系统支持硬链接。安装不改 `AGENTS.md`、`CLAUDE.md`、全局配置或忽略规则，不因为读取或复制就安装；移出看板或重新指向不会删除原项目的 Skill。安装与项目登记不是跨文件事务，登记失败前已创建的文件会保留。

目录依据：[Codex 官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)、[OpenCode Skills](https://opencode.ai/docs/skills/)、[Claude Code Skills](https://code.claude.com/docs/en/skills)、[TRAE Skills](https://docs.trae.cn/ide_skills)。这实现了发现入口和规范分发，尚未实测四家 Agent 在真实会话中的发现与回写遵从率；可刷新工具的 Skill 列表或重启 Agent。Skill 不会主动启动 Agent，也不会绕过工具权限。

## Agent 署名与工作留痕

侧栏“Agent 名单”初始提供 Codex、OpenCode、Trae，可每行填写一个名称保存，也可清空。名称不区分大小写去重，最多 50 个，每个不超过 60 字符，不能含控制字符、冒号或 `·`。名单是交接时的选择项，移除或改名不会更改历史署名。未选署名时，交接词要求 Agent 向你确认，不猜测具体模型。

任务行上的 `@codex` 等标签表示原计划交给谁；本次贡献由实际参与者在收工时署名。项目页“工作留痕”以 Markdown 展示 `TASKS.md` 中的同名分节：

```markdown
## 工作留痕

- 2026-10-16 · Codex：定位渲染入口；任务完成，未验证。
- 2026-10-17 · OpenCode：调整材质处理，兼容修复仍在进行；npm test 通过，界面未验证。
```

每轮追加实际贡献、对应任务状态和验证结果，部分推进也能留痕。交接摘要可以更新，已有留痕保留；同一轮不要重复追加。留痕是 Agent 自述，不代表案屿独立验证结果。案屿不会因点击复制就生成工作记录，仍需把指令交给外部 Agent，回写后刷新。没有留痕的旧文件照常读取，首次回写时再新增分节。

首次自动创建模板使用同目录硬链接发布完整文件，适用于 NTFS 等支持硬链接的文件系统。遇到不支持的文件系统时会给出提示，可手动创建 UTF-8 的 `TASKS.md` 后重新添加；不会降级为覆盖写入。

首页快捷键：`j` / `k` 选择项目，`Enter` 查看，`c` 复制开工词，`Esc` 取消选择。输入时暂停全局快捷键。

## 文件与恢复

默认清单在 `%USERPROFILE%\.isle\projects.txt`，格式为 `绝对路径<TAB>可选项目名`，支持空行和 `#` 注释。坏行会给提示，其他项目保留。移出看板只删除清单条目，不删除项目文件。离线项目可重新指向目录。

全局 Agent 名单保存在同目录 `settings.json` 的 `agents` 数组。保存会保留其他设置字段，页面接口只返回名单及冲突校验值，不返回其他设置内容。设置损坏时不覆盖原文件，项目记录仍可读取；设置在编辑期间被修改时拒绝覆盖，重新打开名单后核对再保存。

`TASKS.md` 是唯一任务、交接摘要和贡献记录数据源。已有文件的 BOM、换行和未编辑内容保持原样；保存 `next` 或交接摘要仅改相应内容和 `updated`，保留工作留痕，不重排任务。两类编辑共用备份和冲突检测；文件被外部修改时拒绝覆盖，界面保留输入供核对。备份、临时文件准备失败时不替换原文件。

每次实际编辑前在项目目录生成 `TASKS.md.bak`，保存上一次写入前的完整字节。为识别本产品备份、防止覆盖用户自己的同名文件，`.bak` 使用带格式标记、目标路径和 SHA-256 的 JSON 容器，原文字节以 Base64 保存。它不是另一份任务源。未知格式的同名备份会阻止写入，需先另存。可这样导出备份原文：

```powershell
npm run restore -- "D:\work\my-project" "D:\work\my-project\TASKS-recovered.md"
```

导出文件必须不存在；此命令不覆盖 `TASKS.md`。核对原文后再自行恢复。`.bak` 只保留一份，不能替代项目的长期备份或 Git 提交。原子替换避免半截文件；不承诺消除所有外部程序并发写入的竞争窗口。

可通过环境变量 `ISLE_HOME` 指定状态目录、`ISLE_PORT` 指定起始端口，例如：

```powershell
$env:ISLE_HOME = Join-Path $PWD '.local-state'
npm start
```

应用只监听 `127.0.0.1`，校验 Host、Origin 和会话，写接口只接受 JSON。项目路径必须手动注册，拒绝链接跳转；不遍历目录，不访问外部服务。v0.1 不含模型、任务状态编辑或拖拽。

## 提交与分支

改动走短生命周期分支再合并，不直接提交到 `main`：

- 设计与方案修订用 `design/<主题>`，功能用 `feat/<主题>`，修复用 `fix/<主题>`，文档与流程类用 `chore/<主题>`
- 本地 `main` 只做快进（`git merge --ff-only origin/main`），不承接直接提交；发现落后先快进，再开分支
- 推分支后开 PR 合并，合并后删除远端分支；`backup/<日期>` 一类分支只是改动集中前的临时保险，确认无需要后同样删除
- 同一轮改动涉及的 `TASKS.md` 任务与`## 工作留痕` 跟着代码走，不拆成另一个 PR；署名写实际参与者

`gh` 未安装时用网页建 PR，分支名仍保持上面的前缀，便于按类型区分。这条约定本身就是一次 PR 的产物：v0.12–v0.13 的改动曾先直推 `main`，随后重做为 `design/v0.12-v0.13` 分支并走 PR #1 合并。

## 验证

```powershell
npm test
npm run build
```

自动检查覆盖脏文件容错、状态冲突、已有文件不变、BOM/CRLF、备份与并发写入、目录离线和重指向、清单坏行、链接防护、本机 API 认证，以及项目 Skill 安装、取消安装、补齐、同名冲突与短指令。首屏数据渲染耗时可在浏览器 Performance 中查看 `isle:projects-render`，项目卡片容器也记录 `data-render-ms`。真实项目三天使用验证仍需实际完成，不能用自动检查替代。
